# Apeos 1.0.1

A maintenance release. No behaviour changes: the two apps do exactly what 1.0.0 did.
Everything below is internal, and the whole reason for the release is that the source
now compiles clean under the Swift 6 language mode rather than carrying warnings that
become errors there.

**[Documentation](https://tony-nz.github.io/ApeosManager/documentation.html)** ·
**[Overview](https://tony-nz.github.io/ApeosManager/)**

## Fixed

- **Quota refresh reads its own constants without borrowing the main actor.** The job
  scan bound and the number of jobs kept were main-actor isolated, but are read from the
  per-printer read that deliberately runs off it. They are immutable integers, so they
  are now declared `nonisolated` rather than sharing the monitor's isolation.
- **The lenient decoder's fallback no longer relies on a no-op cast.** The helper that
  lets one absent field pass without discarding an otherwise valid device response was
  written with a conditional downcast that did nothing; the fallback itself was already
  doing the work. Missing keys and nulls resolve to the same values as before.
- **A discarded cleanup result is discarded explicitly.** Removing a half-made address
  book entry ignores its outcome on purpose, and now says so.

## Notes

- macOS 14 or later. Universal — Apple silicon and Intel.
- Signed with a Developer ID certificate and notarised by Apple.
- Both apps talk only to the printers you configure. No account, no telemetry, no update
  check, no external service.
- Not affiliated with or endorsed by FUJIFILM Business Innovation. The device API is not
  published by the vendor; it was derived by observation and verified against hardware.
